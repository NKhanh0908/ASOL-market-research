# P4.3 AI Recommendation Review UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user explicitly request, inspect and revisit evidence-linked AI recommendations without disrupting existing research pages.

**Architecture:** Add a small recommendations router to the existing FastAPI/Jinja application and reuse its session/CSRF handling. A server-signed preflight binds confirmation to exact evidence/scope/cost policy; one worker executes a persisted request. Two dedicated views provide history and immutable run details without changing the five primary navigation destinations.

**Tech Stack:** Python 3.12, FastAPI, Jinja2, itsdangerous, plain JavaScript, existing CSS tokens, pytest/TestClient, browser verification.

**Spec:** `docs/superpowers/specs/2026-09-25-p4-review-ui-design.md`; prerequisite plans `2026-09-25-p4-ai-storage.md` and `2026-09-25-p4-recommendation-engine.md`.

## Global Constraints

- Dashboard action text: **Tạo gợi ý AI**.
- “Input scope inherits the Dashboard's selected analysis date and market selection.”
- “Disable submission if provider/guardrail is missing, exhausted, or the evidence preflight blocks.”
- “A new explicit run is a new billable attempt.”
- “P3 charts/tables remain available and unchanged in every P4 state.”
- “Buttons and links have text labels; icons are local inline SVGs and decorative when paired with labels. Keyboard focus remains visible.”
- Latest user-approved palette supersedes old navy wording: charcoal surfaces, iris actions,
  jade evidence accents and amber warnings. Reuse current `app.css` tokens; no page redesign.
- No automatic evaluation after crawl or cron; no chat, prompt editor, numeric rating or paid fallback.
- Retain all existing routes. This plan is offline-testable with injected provider fakes;
  production AI remains disabled until the separate provider decision is approved.

## File map and route contract

Create `src/casual_scout/web/recommendations.py`,
`web/templates/recommendations.html`, `web/templates/recommendation_run.html`,
`web/static/recommendations.js`, `web/static/recommendations.css`;
create `tests/test_ai_web.py`, `tests/test_ai_web_security.py`.
Modify `web/app.py` to wire the router/engine/worker and `web/templates/dashboard.html`
to add the explicit action/history link. Do not modify collectors or Android JavaScript.

```text
GET  /recommendations                 history (newest 50) + latest run link
GET  /recommendations/{run_id}        immutable scope/result/status view; 404 if absent
GET  /api/recommendations/{run_id}    safe persisted run projection, no network
POST /api/recommendations/preflight  body: {analysis_date: YYYY-MM-DD, market: all|code}
POST /api/recommendations/runs       body: {quote: signed-string, confirm_unknown: boolean}
```

`recommendation_router(repo, templates, security, engine, worker) -> APIRouter` consumes
P4.1 `EvaluationStore` through the engine and P4.2 `prepare/submit/run`. Expose no generic
user-supplied provider endpoint, prompt, model or input payload.

Preflight responses:

```json
{"state":"blocked","run_id":"persisted-id","reason":"provider_not_configured"}
```

```json
{"state":"ready","quote":"signed-token","scope":{"analysis_date":"2026-09-25","markets":["vn"]},
 "provider_id":"test-only","model_id":"fixture-v1","estimated_cost_usd":null,
 "max_cost_per_run_usd":"0.10","requires_unknown_confirmation":true,
 "warnings":["No comparable multi-market history"]}
```

These are response shapes, not chosen production pricing. Successful confirmation returns
202 `{run_id, url}`. Repeat confirmation with the same quote returns the existing run and
does not dispatch again. Errors: 403 CSRF/origin, 409 stale quote or active-run conflict,
422 invalid scope/unconfirmed unknown cost, 404 missing run. All model calls happen in worker.

- [ ] **Step 1: Add TestClient fixtures and explicit no-call tests.** Extend `create_app` with
  keyword-only `ai_provider: Provider | None = None` and `ai_settings: AISettings | None = None`;
  existing parameters and behavior remain intact. Define `ai_client` in `tests/test_ai_web.py`
  using `FakeProvider` from `tests/ai_support.py`, an initialized temporary repository and
  `seed_ai_evidence(repo)` from `tests/ai_support.py`, defined concretely in P4.2 Task 1.
  Use a no-op collector scheduler,
  so tests cannot start an iOS/Android crawl. Set up CSRF exactly as current Android tests:

```python
def test_preflight_requires_csrf(tmp_path):
    from fastapi.testclient import TestClient
    from casual_scout.config import Settings
    from casual_scout.web.app import create_app
    with TestClient(create_app(Settings(tmp_path)), base_url="http://127.0.0.1:8000") as client:
        response = client.post("/api/recommendations/preflight",
            headers={"Origin": "http://127.0.0.1:8000"},
            json={"analysis_date": "2026-09-25", "market": "vn"})
        assert response.status_code == 403
```

  Also assert GET dashboard/history/status never calls provider; missing configuration creates
  a blocked run via the explicit action only; confirmed quote creates one run and one call;
  replay reuses it; changed evidence/provider/policy requires fresh confirmation; tampered,
  expired or other-session quotes are rejected. Mock demo directory rejects AI POST with 403.
- [ ] **Step 2: Run** `python -m pytest tests/test_ai_web.py tests/test_ai_web_security.py -q`;
  confirm missing routes/signatures cause failures.
- [ ] **Step 3: Implement router and lifespan wiring.** Resolve `all` to configured verified
  market codes, not the hard-coded `/11` label or every chart ever stored. Validate ISO date,
  maximum 12 codes, and market membership before preparing. Both POSTs must pass origin
  middleware and explicit `security.validate_csrf_token(header, session_cookie)`.
  Reuse session cookies issued on Dashboard; do not put keys in HTML or JSON.

  Sign quote using `URLSafeTimedSerializer` with separate salt `casual-scout-ai-preflight`;
  initialize it from the existing server secret, not a browser value. Five-minute expiry,
  tied to session ID, request key, selected scope, input hash, provider/model IDs, prompt and
  schema versions, policy hash, estimate and confirmation requirement. Serialize safe hashes
  rather than the whole evidence payload into the token. On confirmation:

```python
claims = quote_signer.loads(body.quote, max_age=300)
if claims["session_id"] != session_id:
    raise HTTPException(403, "Invalid confirmation session")
existing = find_existing_request(claims["request_key"])
if existing is not None:
    return existing_run_response(existing)
preflight = engine.prepare(claims["analysis_date"], tuple(claims["markets"]))
if frozen_hashes(preflight) != claims["hashes"]:
    raise HTTPException(409, "Dữ liệu hoặc cấu hình đã đổi; vui lòng xác nhận lại.")
preflight = replace(preflight, request=replace(preflight.request,
                                             request_key=claims["request_key"]))
run = engine.submit(preflight, confirm_unknown=body.confirm_unknown)
worker.submit(run["id"])
```

  Define router-local helpers: `find_existing_request(key: str) -> dict | None` queries
  `ai_evaluation_runs.request_key` then `store.get`; `existing_run_response(run: dict)` returns
  JSONResponse 202 `{run_id: run['id'], url: '/recommendations/' + run['id']}`;
  `frozen_hashes(preflight: Preflight) -> dict` returns SHA-256 of canonical input/policy plus
  provider/model/prompt/schema version values. The unique request key + atomic claim remains
  the final race guard even when two POSTs pass the initial lookup concurrently.
  Add worker startup orphan recovery and shutdown cleanup to existing lifespan without
  changing AndroidCoordinator start/stop semantics. Default `ai_provider=None`; do not
  install or construct a network provider implicitly.

  `public_run` includes status, scope, timestamps, result, manifest observations, warnings,
  reported usage, actual cost/method and safe error only. Exclude system prompt, auth/config
  secrets, internal file paths and raw provider envelopes. History GET returns no model input.

  retained CSRF on existing collection routes.

  Each recommendation renders in this order:

```html
<article class="card ai-recommendation">
```

  Populate observations strictly by resolving `evidence_id` to the frozen manifest: show
  platform, market, timestamp/day, metric/value/unit, and `/evidence/{raw_hash}` when available.
  Game links include `snapshot_id`; warn that taxonomy shown by current game detail may have
  been recalculated, while the AI evidence panel remains frozen. Render estimates with
  prototype/MVP scope, feature assumptions, roles and min–max people/weeks. Display all rubric
  explanations, risks, unknowns and validation questions. Zero recommendations gets a clear
  “Chưa có gợi ý đủ căn cứ” message, not three empty cards. Partial coverage is visibly labelled.
  Show safe failure category and unknown billing separately; use “Tạo lượt mới” to re-enter
  preflight, not an automatic retry button. No raw JSON dump is the primary UI.

  Status polling: GET status every 2 seconds while queued/running; stop on any terminal state
  or page unload; on fetch error show status warning and an explicit refresh action. On terminal
  transition reload the immutable detail once. Never poll by POST or repeatedly append model
  output using innerHTML. `role='status' aria-live='polite'` announces progress without focus theft.
